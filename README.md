# Making Spring Boot Migration Easier with Gen AI

Recently, we started an initiative to migrate our microservices from Spring Boot 3 to Spring Boot 4.

Initially, it looked like a regular framework upgrade, but as we started looking into it, we realized there were quite a few things involved. Apart from updating the Spring Boot version, we had to check dependency compatibility, replace APIs that were no longer supported, update configurations and make sure our existing functionality continued to work.

Since we had multiple microservices, doing all these changes manually would have taken considerable time. Also, most of the migration activities were similar across services, so we would have ended up repeating the same work.

This was where we decided to try a different approach using Gen AI.

We were already using GitHub Copilot for day-to-day development, but this time we wanted to see whether we could use it for something more than code suggestions.

We configured a migration agent locally using FPS Dev Assist resources. The idea was to give the agent a specific responsibility: help developers migrate an existing Spring Boot application to the newer version by following a consistent set of steps.

Instead of asking Copilot to make individual changes in different files, we used the agent to assist with the overall migration process.

The agent helped identify dependencies that needed upgrading, suggested replacements for framework APIs, updated configuration files and supported code refactoring. We also used OpenRewrite-based transformations to automate some of the repetitive migration changes.

One useful part was how it helped us deal with compilation issues. After the initial changes, we could use Copilot and the agent to investigate errors and suggest fixes, rather than manually searching for every compatibility issue.

Of course, not everything generated by AI was correct.

A suggested dependency version might not be compatible with another library, or a code change might resolve a compilation error without necessarily preserving the original behaviour.

This was something we had to be careful about.

We treated the AI-generated changes as proposed changes rather than assuming they were ready to merge. We reviewed the dependency updates, checked the modified code, compiled the application and ran our existing unit tests.

We also used Copilot to help update test cases affected by the framework changes. However, we still needed to review those tests to make sure they were validating the expected behaviour rather than simply passing after the migration.

Another area where AI helped was understanding the migration impact. Instead of manually going through every modified file to prepare notes, we used it to summarize the important changes and document areas that developers needed to review.

As we worked through the migration, we found that the agent was particularly useful for repetitive changes that followed a common pattern.

This also helped us maintain consistency across microservices. Developers were no longer approaching every migration from scratch, and we could reuse the same migration approach across different services.

Based on our experience, we estimated that the AI-assisted approach reduced manual migration effort by around **40–50%**. It also helped us identify compilation and compatibility issues faster, which reduced the overall time spent on migration activities.

One thing I learned from this experience was that AI works better when the task is clearly defined and the output can be verified.

For example, dependency upgrades, configuration changes and common API replacements were good candidates for automation. But changes involving business logic or application-specific behaviour still required careful review.

I also realized that getting the application to compile successfully was only one part of the migration. We needed to make sure the application continued to behave as expected.

If I were approaching a similar migration again, I would spend more time preparing a common migration checklist and identifying application-specific dependencies before running the agent. This would make the generated changes easier to review and reduce unnecessary rework.

Overall, this was a good experience because we used Gen AI not just to write code faster, but to simplify a larger engineering activity.

The migration agent helped with repetitive work, while Copilot supported analysis, troubleshooting and testing. This allowed us to spend more time reviewing important changes rather than manually performing the same framework updates across multiple services.

For me, the biggest takeaway was that **AI is most useful when it handles repeatable engineering tasks, while developers remain responsible for correctness and the final technical decisions.**
